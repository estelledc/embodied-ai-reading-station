### 4.2 T014：PR 运行证据已形成，仓库保护仍待 owner

Draft PR #9 已证明 PR workflow 会在合并前运行 `Validate pull request / build` 并成功结束，同时没有触发 Pages upload/deploy job。这个运行结果只证明工作流可执行，不能声称 GitHub 仓库保护已经生效。owner 仍需：

1. 把实际 check `Validate pull request / build` 设为 main 的 required status check。
2. 为 main 启用 required pull request、禁止 force push 和 branch deletion。
3. 合并后确认 main build/check 成功，且 Pages deploy 只从 main 执行。

实际 required check 与 main protection 仍是 T014 的剩余证据；合并后 main/Pages 成功记录已关闭 T015 的部署验证缺口，但不能替代 T014 的 owner 设置。

依赖处理原则：

- `EAI-T008` 与 `EAI-T011` 存在 schema/provenance 互相约束，作为一个设计批次冻结合同，但仍按 T008 数据来源 → T011 公共 API 的顺序落地。
- `EAI-T010` 是 `EAI-T018` 的性能与响应式前置条件。
- `EAI-T013` 必须建立在 T011 的版本化数据语义之上，避免离线缓存无法识别 schema 变化。
- `EAI-T016` 复用 T005/T021 已完成的 sink 与 protocol 安全边界。
- `EAI-T017` 与 `EAI-T018` 联合验收，不能只改 ARIA 文案而不做键盘、焦点和窄屏实测。
- `EAI-T019`、`EAI-T020` 复用 T008 provenance 合同；P2 未阻塞历史上的 v1.2 发布。
