# 阶段 2：跑通 VLM_Grasp_Interactive（Task 2 基础项）

导师给的基础项目是 [hangtingLiu/VLM_Grasp_Interactive](https://github.com/hangtingLiu/VLM_Grasp_Interactive)。这一页帮你在动手之前弄清楚三件事：它到底在做什么、你的机器能不能跑、先跑哪一块。

> **诚实说明**：这一页是按那个项目的 README 和代码（2026-09 查看，默认分支 `master`）整理的。本仓库的云端环境没有 NVIDIA 显卡，**没有真正跑通过这个项目**。你自己跑通之后，把真实过程写进 [`../logs/`](../logs/)。

## 它在做什么

一句话：你对着麦克风说"把小黄鸭递给我"，仿真里的 UR5e 机械臂就去抓那只鸭子（场景素材里有鸭子、手电筒、锤子、小刀等物体）。中间是一条"流水线"，每一段交给一个不同的模型：

```text
你的语音
  → Whisper：语音转成文字
  → Qwen 多模态模型（通过兼容 OpenAI 的接口调用）：看相机图像 + 读文字，回答"要抓的是哪个物体"，给出它在图里的方框
  → SAM：按方框把这个物体从图里精确抠出来（掩码）
  → GraspNet-baseline：用 RGB-D 图像变成的点云 + 掩码，算出夹爪该从什么位置、什么角度去抓
  → 机械臂在 MuJoCo 里按这个抓取位姿执行
```

对应的代码文件：`main_vlm.py`（主程序）、`vlm_process.py`（Whisper + Qwen + SAM）、`grasp_process.py`（GraspNet 推理与执行）、`manipulator_grasp/`（MuJoCo 里的 UR5e 场景）。

## 和 13 篇任务论文的关系

这条流水线里的每一段，都能在任务论文里找到"为什么这么做"和"还能怎么做"：

| 流水线里的环节 | 对应的论文 | 读的时候想什么 |
|---|---|---|
| Qwen 看图找目标 | LLaVA | 图像是怎么变成语言模型能读的 token 的（练习 1） |
| VLM 决定抓什么，GraspNet 决定能不能抓、怎么抓 | SayCan | "语言决定做什么 × 可行性决定怎么做"的分工 |
| 语音先转成文字再交给模型 | VLAS | VLAS 恰好主张不经过文字、直接用语音；转写出错会怎样？ |
| GraspNet 用的点云 | MLA、3DShape2VecSet | 3D 信息该怎么表示、怎么和图像一起用 |
| 换成一个模型直接输出动作 | OpenVLA、SmolVLA | 这就是阶段 3 要做的"端到端"路线 |

## 先确认机器能不能跑

在你打算用的机器上运行：

```bash
python check_env.py
```

它只检查、不安装。最关键的两条：

1. **要 Linux + NVIDIA 显卡。** 这个项目要编译 PointNet++ 和 k-NN 的 CUDA 算子，Mac 没有 CUDA，跑不了。手上没有合适的机器，就先找导师或学长要实验室服务器的账号，或者租一台云 GPU。
2. **要 Python 3.10 的独立环境。** README 用的是 `torch==1.12.1+cu113`，这个版本没有 Python 3.11 及以上的安装包。

还需要一个多模态模型的 API：`vlm_process.py` 里的 `OpenAI(api_key='', base_url='')` 要填你自己的密钥和地址。**不要把密钥提交到 GitHub。**

## 建议的顺序：一段一段地验证

不要一上来就运行 `main_vlm.py`。整条流水线里任何一段出错，报错信息都会很难懂。按下面的顺序，每一步都成功了再往下走：

1. 先看项目 README 里附的 B 站视频，知道"跑通"是什么样子。
2. 只打开 MuJoCo 场景：能看到 UR5e 和桌上的物体。
3. 从场景里取一帧彩色图和深度图，存成文件看看。
4. 单独运行 SAM：在这张渲染图上框一个物体，能得到掩码。
5. 单独运行 GraspNet-baseline 自带的 `demo.py`：用它的示例数据算出抓取位姿。
6. 单独调用一次 Qwen API：发一张图和一句话，拿回物体名字和方框。
7. 最后把它们串起来运行 `main_vlm.py`。

每一步都记下：运行了什么命令、看到了什么、报了什么错、怎么解决的。模板在 [`../logs/TEMPLATE.md`](../logs/TEMPLATE.md)。

## 可能会遇到的坑（按经验整理，本环境没有验证）

- **torch 1.12 和 NumPy 2 不兼容**：导入 torch 时报 NumPy 版本相关的错误，就装 `numpy<2`。`check_env.py` 会检查这一条。
- **CUDA 版本对不上**：编译 PointNet++ / k-NN 时，本机 `nvcc` 的 CUDA 版本要和 torch 编译时用的版本（README 里是 cu113）对得上；显卡驱动也要支持这个版本。
- **编译器太新**：老版本 CUDA 往往不支持太新的 gcc，编译报错时先看看错误信息里有没有提到 gcc 版本。
- **`sklearn` 包名**：新版 pip 不再接受 `sklearn` 这个包名（要用 `scikit-learn`）。如果安装 graspnetAPI 时报这个错，就改它的依赖声明或先单独装好 `scikit-learn`。
- **麦克风**：云服务器上没有麦克风，语音那一段可以先用一段录好的音频文件代替。

## 这一阶段的出口

- 一段录屏：说一句话（或输入一句指令），机械臂抓起了对应的物体；
- 一份踩坑记录：每个报错、你查到的原因、最后怎么解决的。

做到这两样，就可以进入阶段 3。
