# Acoustic Swarms：让一群小机器人自己在桌上摆出一张"巨型耳朵"

> 给"完全没接触过 AI / 机器人 / 音频信号处理"的读者写的精读笔记。所有专业词第一次出现都会解释清楚。只看这份笔记就能理解全文机制。

---

## 一句话讲什么（TL;DR）

七个骰子大小的小机器人从底座自动爬上桌面、散成一圈，用声波互相测距算出彼此坐标，把整张桌子变成一张分布式大麦克风网。桌边几个人同时说话，它能数出有几个人、定位每个人坐哪、把每个人的声音单独分离出来——全程不需要人手摆放、不需要头顶摄像头、不需要给机器人连线。

*所以这一节是想说：这是一群"自己布阵"的小麦克风机器人，把单设备无法做到的多人语音分离变成了现实。*

---

## 这是个什么场景

周末聚餐，一桌六个人围着火锅，姑姑在跟你妈聊孩子，舅舅在讲股票，小表弟在抢虾滑——三波话同时在飞。你掏出手机想给奶奶录一段，回放时只剩一锅"嗡嗡嗡"，连自己说的那句"干杯"都挑不出来。

原因很简单：手机就一只耳朵，蹲在桌中央。它分不清"对面那位"和"左手边那位"是两个不同的人。

那人为什么能分清？因为你有两只耳朵，左右隔着十几厘米。同一个声音先到左耳、再到右耳，两边差那么一丁点时间，大脑就能反推出"声音从左前方来"。麦克风也一样——只要把好几只麦克风摆得离得远，就能靠"时间差"把不同方向的人拆开。

这里就要引入一个关键概念：

> **Aperture（阵列张开尺度/孔径）**：一组麦克风里最远那两只之间的距离。类比望远镜的镜面直径——直径越大，看得越清楚。同理，麦克风阵列摊得越开，分辨不同方向声音的能力越强。

但问题是：谁会在火锅桌上量好坐标、摆 7 只麦克风、再扯一堆线连到电脑？这事得让机器自己来办。

再拉远一步看"听觉三连"——在本导读的 13 篇论文里，听觉方向有三篇互相配合的工作：

| 层次 | 论文 | 干什么 |
|------|------|--------|
| 硬件/阵列层 | **Acoustic Swarms（本篇）** | 把麦克风从 1 个变成 14 个，分布在桌面上 |
| 神经处理层 | NeuralAids | 把降噪网络压缩到助听器芯片里运行 |
| 决策/意图层 | Proactive Hearing | 自动判断"你在跟谁聊"，只放大对话伙伴 |

本篇是整个听觉链条的"地基"——如果硬件上只有一两只耳朵，再聪明的算法也分不出五个人。Acoustic Swarms 把"耳朵"从一对扩展到了七对，且全部自动化。

*所以这一节是想说：单麦克风分不清多人说话；要分清就要把麦克风摆远，但人手摆不现实——这篇就要让机器人自己来做。*

## 之前的人怎么做的，为什么不够好

学术界其实做了很多"小机器人群"的工作，但都被某些条件卡死。下面按路线分类：

| 路线 | 代表工作 | 做法类比 | 致命问题 |
|------|----------|----------|----------|
| 头顶摄像头定位 | 多篇（Yu 2017 等） | 体育馆的鹰眼系统——天花板装相机俯拍 | 离开"体育馆"就没法用；且摄像头有隐私问题 |
| 投影仪定位 | Zooids (2016) | 舞台灯光打条纹——机器人靠看投影知道自己在哪 | 撤了灯就摸瞎；需要专用投影设备 |
| 红外测距 | Kilobot (2014) 等 | 近视眼——两台机器人互发红外光测距 | 有效距离 < 10 cm，机器人散不开 |
| IMU 自估算 | Mona / Hero 2.0 | 闭着眼走路——靠"我向前走了几步"推位置 | 走十步还行，走五十步就偏到墙角（累积漂移） |
| 分布式麦克风阵列 | 多篇（ICASSP 等） | 把多个有线麦克风固定在已知位置 | 要事先量好坐标、用线连起来、只能在实验室里用 |
| 神经网络语音分离 | SepFormer / Conv-TasNet | 给定混合音频，算法把各人声音分开 | 不能定位说话人在空间的哪个位置；且大多要求预知人数 |

核心矛盾是：没有任何一个系统能同时做到三件事——（1）自己散开到大面积、（2）厘米级精度自我定位、（3）多人语音分离。要么靠外部设备，要么测距太短，要么会漂移，要么只做分离不做定位。

*所以这一节是想说：以前的方法各有硬伤，没有人把"自动布阵 + 精确自定位 + 多人分离"三件事一起做到。*

## 这篇论文的新想法

类比一下：你做饭时让小米的扫地机器人自己出基站、绕家一圈、回基站充电——它知道自己走过哪。这篇做的是同款故事，只不过主角换成"会爬桌的小麦克风"，而且完成任务后变成一张分布式大耳朵。

具体说，作者做了三件同行从未一起做过的事：

1. **造了硬件**：设计并制造了 3 cm x 2.6 cm x 3 cm 的厘米级小机器人，每台带 2 个麦克风 + 1 个扬声器 + IMU + 蓝牙 + 电池 + 边缘检测传感器。七台一组从底座自动爬出来。
2. **设计了布阵算法**：机器人用声波互相"喊一嗓子"测距、用底座轨道上的已知标记消除定位歧义、按等分角度往外扩散、碰到桌沿或物体就停。全程不需要任何外部设备。
3. **设计了语音分离算法**：把 7 台机器人的 14 路麦克风信号汇总，先用经典信号处理做粗定位、再用神经网络做精定位 + 分离，最后用"说话人间注意力"机制压串音。事先不需要知道有几个人。

一句话：机器人自己当摆放工、自己当坐标系、自己当分离引擎。没有头顶相机、没有投影仪、没有人帮忙摆。

*所以这一节是想说：核心创新是"硬件 + 自动布阵 + 分离算法"三合一，前人各只做了其中一块。*

## 它分几步做的（方法）

整个流程像七个小演员演一出戏：从化妆间排好队 → 一个个上台站位 → 报告各自坐标 → 开始听观众说话 → 结束后回化妆间充电。下面按顺序展开。

### Step 1：硬件——骰子大小的机器人长什么样

**输入**：一个"做分布式麦克风阵列"的需求。

**处理**：

每台机器人的核心是一颗蓝牙低功耗模块（ISP-1807），里面包了一个微控制器（Nordic nRF52840）。在这颗芯片周围搭了一整套传感器和执行器：

| 部件 | 型号 / 参数 | 干什么 |
|------|-------------|--------|
| 陀螺仪 + 加速度计 | ISM330DLCTR + MC3419 | 测旋转和加速，用来推算走过的路（里程计） |
| 两个麦克风 | ICS-41352 | 录音；两个麦克风在一台机器人上形成"迷你双耳" |
| 一个扬声器 | AS01008MR-3 + Class D 放大器 | 发射超声波 chirp，用于测距 |
| 两个光电对管 | GP2S700HCP | 检测桌子边缘——朝下发红外光，桌面在时反射回来，悬空就没反射 |
| 两个微型电机 | FA-GM6-3V-25 | 左右轮驱动移动 |
| 电池 | 3.7V 100mAh 锂聚合物 | 提供能量 |
| 充电器 + 电量计 | LTC4124 + MAX17048 | 支持在底座上通过铝球接触充电 |

> **BLE（蓝牙低功耗）**：蓝牙的一个子协议，特点是功耗极低，但带宽也低（约 2 Mbps）。类比你打电话时选"省电模式"——电池撑得久但通话质量有限。

整台机器人只有 3 cm x 2.6 cm x 3 cm，比一颗骰子大不了多少。底部有两颗铝球，放到底座的导电轨道上就能充电——像老式玩具火车在铁轨上取电。

**底座设计**：底座是一个 3D 打印的塑料平台，里面有弯曲的槽轨和入口/出口斜坡。槽轨上每隔一段有黑色标记（checkpoint），机器人靠光电对管识别这些标记来知道自己在底座里的位置。导电胶带贴在槽轨上，接 6V 直流电给所有机器人同时充电。

**音频流传输**：每台机器人把 16-bit、48 kHz 的录音用 Opus 编解码器实时压缩到 32 kbps，通过蓝牙传到主机（笔记本电脑）。受蓝牙带宽限制，7 台同时传输时刚好不丢包。

> **Opus Codec**：一种开源的音频压缩格式，微信语音通话、Discord 等都用它。特点是极低延迟 + 较小体积。

**输出**：一组可以自主移动、自主充电、能发声/录音/测边缘的厘米级机器人。

*所以这一节是想说：每台机器人麻雀虽小五脏俱全——双麦克风、扬声器、IMU、边缘检测、蓝牙、电池、充电，全塞在 3 厘米见方的壳子里。*

### Step 2：用声音测距——"打雷数秒数"的工程实现

**输入**：七台已经散开在桌面上的机器人，彼此不知道对方在哪。

**处理**：

基本原理极其简单：一台机器人用扬声器发一声，另一台用麦克风听，记下声音飞行的时间 Δt，乘以声速 c（约 343 m/s），就是两台之间的距离 d = c × Δt。

但魔鬼藏在细节里：

**细节 1：用 chirp 而不是"嘀"一声**

> **Chirp（扫频信号）**：一段几毫秒长的声音，频率从低到高（或从高到低）连续滑动，像警车鸣笛由低变高。

为什么不用一声简单的"嘀"？因为屋子里有回声。声音会先直线到达对面机器人（直达路径），然后从墙壁/桌面弹回来再到达（反射路径）。一声短"嘀"和它的回声混在一起，你分不清哪个是原声、哪个是回声。

但 chirp 的频率在时间上是变化的——电脑可以用一种叫**匹配滤波（matched filter）**的方法，把收到的信号和发出的 chirp 做"互相关"，只有完美匹配的那个时刻才会产生一个尖峰。这个原理和雷达完全一样——雷达发的也是 chirp，就是靠这个尖峰来精确测距的。

> **匹配滤波 / 互相关**：把"你期望收到的信号模板"和"实际收到的信号"一帧一帧对比，完全对上的那一刻会产生一个响应峰值。类比你在一堆杂音里找一段特定的旋律——你把旋律当模板，逐秒滑过去，旋律出现的时刻匹配分数最高。

本文的 chirp 以 62.5 kHz 采样率发射，频率范围在超声波段（大于 20 kHz），人耳听不到，不会干扰说话的人。

**细节 2：全局时钟同步**

要算"飞行时间"，发射方和接收方的时钟必须对齐。如果 A 的时钟比 B 快 1 毫秒，那所有距离都会偏 34 厘米——完全不可用。

作者设计了一个全局时钟同步算法（论文附录有详细描述），把所有机器人的时钟误差控制在 62.5 kHz 采样率下的 1 个采样点以内，即 16 微秒。16 微秒乘以声速只有 0.55 厘米的距离误差，对后续定位够了。

**细节 3：双麦克风去多径**

每台机器人有两个麦克风。直达路径的声音到达两个麦克风的时间差取决于声源方向，而反射路径到达的时间差是不同的。通过比较两个麦克风的信号，可以更好地锁定"第一个到达的直达路径"，把反射路径的干扰剔除掉。

> **多径（multipath）**：声音经过墙壁、天花板、桌面反射，产生多条路径同时到达接收器。类比山谷里的回声——你喊一声，几秒后听到好几次回声，每次是不同的反射路径。

**输出**：任意两台机器人之间的 1D 距离估计。

**关键数字**：

| 指标 | 数值 |
|------|------|
| 时钟同步误差 | ≤ 16 μs（1 个采样点 @ 62.5 kHz） |
| 1D 测距中位误差（空桌） | 0.48 cm |
| 1D 测距中位误差（靠墙） | 0.45 cm |
| 1D 测距 90% 误差 | 1.1–1.2 cm |

*所以这一节是想说：用超声波 chirp + 匹配滤波 + 全局时钟同步 + 双麦克风去多径，实现毫米到厘米级的两两测距。*

### Step 3：从"两两距离"到"绝对坐标"——破解定位歧义

**输入**：所有机器人之间的两两 1D 距离。

**处理**：

光知道"A 离 B 30 cm，A 离 C 40 cm，B 离 C 50 cm"还不够——你只知道三角形的形状，但不知道三角形在桌子上的哪个位置、朝哪个方向。数学上，这套纯距离数据有两个歧义：

1. **平移歧义**：所有点同时往右挪 5 cm，相互距离完全不变——所以你不知道原点在哪。
2. **镜像翻转歧义**：把整个布局沿一条轴线翻转（就像把照片左右镜像），所有距离也完全不变——所以你不知道"上"和"下"。

要破这两个歧义，得有"已知坐标的锚点"——就像地图上必须有经纬度标注，光画形状没意义。

作者的巧妙解法：利用底座轨道上的已知标记（checkpoint）作为虚拟锚点。

**具体流程**：

1. 散开完成后，留一台机器人在底座里。它沿着轨道滑动，每经过一个 checkpoint 就发一次 chirp。由于轨道上 checkpoint 的位置是已知的（制造时就定好了），这就相当于有了好几个"坐标已知的灯塔"。
2. 桌面上的机器人各自记下到每个 checkpoint 的距离——相当于有了"到好几个灯塔的距离读数"。
3. 桌面上的机器人之间再轮流发 chirp，互相补测距离，增加约束条件。
4. 把所有距离数据喂进一个 2D 定位求解器（本质上是一个最小二乘优化问题），反推每台机器人的 (x, y) 坐标。

> **最小二乘优化**：给定一堆"测量值"和一堆"根据位置计算出的理论值"，找一组位置使得所有"测量-理论差值的平方和"最小。类比你用橡皮筋把几个钉子连起来——橡皮筋拉力最小的状态就是"距离最吻合"的状态。

**为什么 checkpoint 必须在一条直线上？** 因为一条直线就能同时破掉平移和镜像两个歧义——你知道线在哪（破平移），翻转后线上的距离分布会对不上（破镜像）。

**处理 1D 测距的长尾误差**：当桌面上有物体挡在两台机器人之间时，直达路径被遮挡，测出来的距离偏大。这会在 1D 测距分布上形成"长尾"。但 2D 定位优化器可以把这些异常值当离群点处理——因为一台机器人的位置被很多对距离约束着，个别异常对整体解影响不大。

**输出**：每台机器人在底座坐标系下的绝对 (x, y) 坐标。

**关键数字**：

| 指标 | 数值 |
|------|------|
| 2D 定位中位误差（空桌） | 0.37 cm |
| 2D 定位中位误差（靠墙） | 0.38 cm |
| 2D 定位 90% 误差（有物体） | 1.3 cm |
| 不同桌面尺寸的误差变化 | 几乎不变（1.2m–1.8m 桌子均可） |

*所以这一节是想说：用底座轨道上的已知标记当锚点，破解了平移和镜像歧义，把两两距离反推出绝对坐标，精度达到厘米级。*

### Step 4：让机器人自己散开——"切披萨"式扩散策略

**输入**：N 台（通常 7 台）机器人排在底座里，不知道桌子的形状和桌面上有什么。

**处理**：

目标是让机器人尽可能散开，从而让麦克风阵列的 aperture 最大化——aperture 越大，后续语音分离的空间分辨率越高。

整个散开分三个阶段：

**阶段 A：在底座里排队**

机器人被人随手放进底座，顺序是随机的。系统需要先搞清楚"谁排在第几个"。

方法：让一台机器人往前走，它会撞到前面那台（撞击产生加速度尖峰，被 IMU 检测到）。多次这样的"碰撞实验"加上轨道两端 checkpoint 的识别，可以反推出底座里的完整排列顺序。

排序完成后，机器人们重新排列到各自的 checkpoint 位置上——这里要处理"两台都想去同一个标记"的冲突。方法是：除最后一台外，所有机器人先向出口方向移动形成连续链；最后一台退到末端标记；然后从后往前，每台机器人向后退、撞到后面那台、再前进到第一个遇到的标记停下。

**阶段 B：分配出走方向 + A\* 导航**

把 360° 等分成 N-1 份（留一台在底座），每台机器人分一个角度。例如 7 台里 6 台出去，每台分 60°。

但前面几台机器人要走的方向在底座的"后面"——它们需要先绕过底座本身才能朝后散开。这里用 **A\* 算法**在网格上算出绕路的最短路径。

> **A\* 算法**：一种经典的寻路算法。它对每条候选路径打分："已经走了多少（g 值）+ 估计还要走多少（h 值）"，优先尝试总分最低的那条路。类比手机导航——给你推荐的路线就是"已走里程 + 预估剩余里程"加起来最短的那条。

A\* 把绕路的中间点叫做"里程碑（milestone）"。机器人先导航到里程碑，再从里程碑转向自己的分配角度开始径向散开。

**阶段 C：径向扩散 + 边缘/碰撞检测**

到达里程碑后，机器人用陀螺仪转到分配角度，然后直线向外移动，直到不能再走为止。

"不能再走"有两种情况：

1. **到了桌沿**：光电对管朝下发红外光，桌面在时光反射回来，悬空（到桌沿了）就没反射。检测到悬空立刻后退。机器人能在 18 cm/s 的速度下正确检测到边缘。

> **光电对管（photointerruptor）**：一对红外发射器 + 接收器。发射器朝下打光，接收器检测反射回来的光强。桌面反射强，悬空反射弱。类比汽车的倒车雷达，但用红外光代替超声波。

2. **撞到物体**：杯子、书本、线缆都可能挡路。撞到时机器人产生加速度尖峰，超过阈值就判定碰撞，后退避让。最低检测速度 10 cm/s。

**导航过程中的 IMU-声学融合校准**（这个和 Step 5 紧密相关，但在散开阶段就在用了）：

单靠 IMU 推位置会漂移——陀螺仪每秒 0.1° 的噪声，30 秒累积就是 3° 的角度误差，对应米级位置错误。解决方法：正在移动的机器人每 200 毫秒发一次 chirp，留在底座的"灯塔机器人"测距。把"声学测出的真实距离"和"IMU 推算的预期距离"做比较，反推真实位置，纠正漂移。

> **IMU（惯性测量单元）**：一颗能告诉设备"自己在转"和"自己在加速"的小芯片。你手机里也有，计步和屏幕旋转都靠它。但它的小噪声会被积分放大——类比你闭着眼走路，每步偏一点点，走一百步就偏到隔壁房间了。

> **IMU-声学融合导航**：每走一小段就用声波"回头看一眼灯塔"，校准自己的位置。类比你在商场里每走 50 米就看一眼指示牌确认方向，而不是闭着眼全靠步数。

**输出**：N-1 台机器人散布在桌面各处，1 台留在底座作为参考灯塔。

**关键数字**：

| 指标 | 数值 |
|------|------|
| 散开总时间（7 台） | 约 1 分 45 秒 |
| 排序发现耗时 | 约 32 秒 |
| 每台散开耗时 | 11.8 ± 7.0 秒 |
| 散开能耗 | 22.3 J（仅 1.7% 电量） |
| 桌面占用率 | > 75%（所有方向、各种桌型） |
| 边缘检测最高速度 | 18 cm/s |
| 碰撞检测最低速度 | 10 cm/s |

**为什么用"等分角度"而不是更聪明的策略？** 因为机器人事先不知道桌子形状和障碍位置。任何"最优方案"都需要先建图——但建图本身就需要走遍整张桌子，太费时间和电量。等分角度是"不需要任何先验知识、最坏情况下也能凑合"的启发式方法。

*所以这一节是想说：机器人先在底座排好队，再按等分角度散开，碰边缘或物体就停，期间靠声波每 200 ms 校准一次位置。*

### Step 5：听人说话——先定位，再分离

到这里硬件部分搞完了——机器人会自己排队、散开、知道彼此坐标。下面是算法核心：怎么从 14 路（7 台 x 2 麦克风）信号里抽出每个人的话。

算法分两大阶段：**先定位（房间里有几个人，分别坐哪）**，**再分离（给每个人单独一份干净的语音）**。

#### Step 5a：定位——"粗筛 + 细筛"找到每个说话人

**输入**：14 路 48 kHz 音频流 + 7 台机器人的已知 (x, y) 坐标。

**核心思路**：把空间网格化（像棋盘一样切成小格子），对每个候选格子问一个问题——"这个格子里有人在说话吗？"

怎么回答这个问题？靠"对齐 + 检测"：

假设格子 P 处有人在说话。声音从 P 传到 14 个麦克风的路径长度各不相同，对应不同的"到达时间差"。

> **TDoA（Time Difference of Arrival，到达时间差）**：同一个声音被多个麦克风听到的时间差。类比你站在操场上，左边有人喊你名字——声音先到你左耳、再到右耳，这两个时间差就是 TDoA。知道 TDoA 就能推出声源方向。

如果我们按照 P 点对应的 TDoA 把每个麦克风的信号做时间平移（"对齐"），那么：如果 P 处真有人，对齐后所有 14 路信号会"同步"，叠加起来很响；如果 P 处没人，对齐后信号是不相关的噪声，叠加起来很弱。

叠加后越响 = 这格越可能有人。

但为什么要搜索 3D 空间而不只是 2D？因为说话人的嘴巴比麦克风（在桌面上）高——高度差会引入额外的时延。如果只在 2D 平面上搜索，会忽略这个高度差导致的时延偏移，定位就不准。

**两步走**：

**第一步：粗筛——SRP-PHAT**

> **SRP-PHAT（Steered-Response Power with Phase Transform）**：一种经典的声源定位算法。它把所有麦克风对（14 个麦克风有 91 对组合）的"相位差"信息指向每个候选点，算指向后的总能量。能量高的地方就可能有人。计算量小但分辨率粗。

> **相位差**：两个信号之间的时间偏移在频率域的表示。类比两个钟面——时针都指 12 点就是"同相"，一个指 12 一个指 3 就是"差了四分之一圈"的相位差。

SRP-PHAT 的作用是"大范围排除"：把整个 3D 搜索空间中明显没人的区域砍掉。论文报告 SRP-PHAT 可以把搜索空间缩小 200 到 446 倍，效率非常高。

**第二步：细筛——注意力分离网络**

在 SRP-PHAT 留下的少数候选区域里，用一个神经网络做精细判断。这个网络的结构是：

> **U-Net**：一种"沙漏形"神经网络。输入先经过一系列卷积层被"压缩"成紧凑的表示（编码器），再经过对称的一系列层被"展开"回原始大小（解码器）。每一层压缩和对应的展开层之间有"跳跃连接"把细节信息直接传过去。类比你做笔记——先精简到一句话摘要，再展开成段落，但展开时会回头翻原始材料补充细节。

> **Transformer / 自注意力**：一种让序列中任意两个位置"互相看一眼"的计算机制。普通的卷积只看"相邻几个位置"，但 Transformer 可以让第 1 个位置和第 100 个位置直接交互。类比你读一篇文章时，会同时回头看前面的主语和后面的宾语来理解句意，而不是只看相邻的字。

本文的分离网络是 U-Net + Transformer 的混合体：U-Net 做编解码，中间插入 Transformer 编码器作为"瓶颈层"。Transformer 在时间维度上做自注意力——让网络关注"同一个人在不同时刻的语音片段之间的关联"，从而更好地判断这段声音是不是来自一个真实说话人。

> **GLU（门控线性单元）**：U-Net 里面用的一种激活机制。它把输入分成两半，一半作为"信息"、另一半经过 sigmoid 函数变成"门"（0 到 1 的值），两半相乘。相当于网络学会了"哪些信息该放过去、哪些该拦住"。

**四个提高鲁棒性和效率的技巧**：

1. **两级分辨率搜索**：先用大格子粗搜（每格覆盖较大区域），丢弃低响应的格子；再把剩下的格子分裂成更小的子格子做精细搜索。这像拼图——先按颜色分堆，再在每堆里精细拼接。网络通过一个 one-hot 向量知道自己当前在做"大格子模式"还是"小格子模式"。

2. **训练时随机扰动麦克风位置**：故意把训练数据中的麦克风坐标乱挪最多 4 个采样点（对应约 2.8 cm），让网络学会容忍真实部署时的定位误差。这是一种数据增强策略——类比你练投篮时故意站在不同位置投，比赛时位置偏一点也能进。

3. **TDoA 空间离散化**：不在 3D 欧几里得空间里均匀切格子，而是按"等间隔 TDoA 值"来划分——同一个 TDoA 区域里所有点对网络来说"看起来一样"。这样做有两个好处：（a）搜索效率更高，（b）自动适应不同形状的麦克风分布。

4. **幻影声源去重**：由于室内反射，一个真实说话人可能在 SRP-PHAT 输出上产生多个"幻影"——就像镜子里看到两个你。论文用聚类算法把相似的输出合并掉：如果两个候选位置的分离输出听起来像同一个人，就只保留响应更强的那个。

**输出**：房间里的说话人数量 S 和每个人的 2D 坐标。

*所以这一节是想说：定位的核心是"对齐 + 检测"——在候选位置对齐信号看响不响。先用经典算法粗筛砍掉 99% 的空间，再用神经网络精细判断。*

#### Step 5b：分离——用"说话人间注意力"压串音

**输入**：S 个说话人的 2D 坐标 + 14 路麦克风信号。

**处理**：

定位阶段已经知道了每个人在哪。但定位网络顺带输出的分离信号质量不够好——仍有明显的"串音"（你想听 A 说话，结果 B 的声音也漏进来一部分）。

为什么不直接用定位网络的输出？两个原因：
1. 定位网络只关注"这个位置有没有人"，没有优化"输出的声音纯不纯"。
2. 定位阶段还不知道其他人在哪——但现在知道了。可以利用"其他人的位置"来更好地抑制串音。

作者设计了一个专门的分离网络，结构和定位网络类似（U-Net + 瓶颈层），但关键创新在瓶颈层的设计：

**瓶颈层做两件事，交替执行**：

1. **同一人内部的时间注意力（intra-speaker attention）**：用 Conformer 网络在时间维度上处理每个人的信号，抓取该说话人在不同时刻的语音规律。

> **Conformer**：一个混合结构，把"擅长抓局部细节"的卷积层和"擅长看全局关系"的 Transformer 串起来用。类比你读一篇文章——先用眼睛扫相邻几个字（卷积），再回头看全文把主旨串起来（Transformer）。

2. **不同人之间的说话人注意力（inter-speaker attention）**：用 Transformer 在"说话人维度"上做自注意力——让每个人的特征"看一眼"其他人的特征，识别"这段声音是不是从隔壁串过来的"，把串音成分减弱。

这两步交替多次执行，串音一层层被压下去。类比洗衣服——洗一遍可能还有污渍，洗三遍就干净多了。

**架构的一个优美性质**：说话人间注意力是在"说话人维度"上做的，而不是在"时间维度"上。所以不管有 2 个人还是 8 个人，都用同一套网络权重，只是注意力矩阵的大小跟着 S 走。不需要为不同人数训练不同的模型。

**输出**：S 份干净的、每人一份的语音信号。

*所以这一节是想说：知道每个人坐哪后，让网络在同一人内部找规律、在多人之间互相压串音，交替多次，输出每人一份干净语音。*

### Step 6：返航 + 充电——像扫地机器人回充电桩

**输入**：任务完成或电量低，需要让所有机器人回底座。

**处理**：

返航基于两个关键假设：
1. 底座附近有一个半径约 25 cm 的"安全圈"（clear zone），里面没有物体。
2. 散开时每台机器人是直线走出去的，而且这条路径上之后没有新放物体。

返航流程：

1. **同时返回安全圈**：所有外部机器人沿来时的直线路径往回走。底座里的灯塔机器人以 5 Hz 频率发 chirp，外部机器人靠它做实时测距，走到 25 cm 以内就停下。
2. **精确 2D 定位**：所有机器人进入安全圈后，再跑一次完整的 2D 定位算法，更新每台的精确坐标。
3. **依次对接**：机器人按散开的相反顺序，一台一台回底座。
4. **朝向校准**：快到底座入口时，IMU 累积的陀螺仪漂移可能导致朝向偏了。机器人做一次直线运动 + 多次声学测量，反推真实行进方向（即真实朝向），再调整。
5. **进入底座**：机器人做一系列旋转来识别入口轨道的位置，然后前进对接到槽轨上。每一台进入后，底座内的其他机器人挪位置让开，更新自己作为下一台返航的新地标。

**输出**：所有机器人回到底座开始充电。

**关键数字**：

| 指标 | 数值 |
|------|------|
| 灯塔 chirp 频率 | 5 Hz |
| 安全圈半径 | 25 cm |
| 每台返航 + 对接耗时 | 40.4 ± 4.5 秒 |
| 满充时间 | 约 2.5 小时 |

*所以这一节是想说：原路退回 + 灯塔实时校准 + 安全圈精定位 + 旋转对接入坞，全自动完成。*

## 实验结果说明了什么

论文的实验分四层递进，每层回答一个问题：

**第一层：仿真（合成数据）验证算法上限。** 训练数据用电脑模拟虚拟房间，把公开语音数据集（LibriSpeech、VCTK）随机放在不同位置，模拟反射后叠加。2–5 人同时说话时 precision 和 recall 都在 89% 以上，2D 定位中位误差 9–10 cm，SI-SDRi 超过 oracle 方法 IRM 4.8 dB。这说明算法本身的天花板很高。

**第二层：真实房间（干净桌面）验证能不能落地。** 在四种未见过的真实环境（办公室、客厅、实验室、厨房）里测试。Precision 和 recall > 90%，定位中位误差 15 cm。比仿真差一些但没有崩盘——证明算法对真实噪声和混响有鲁棒性。

**第三层：桌面有杂物验证实际使用条件。** 桌上放了手机、笔、笔记本电脑、瓶子、书本、电线——这些物体会遮挡机器人之间的直达路径。结果 precision/recall 仍然 > 90%，定位中位误差 14 cm，分离质量 > 10 dB。说明系统对常见桌面杂物具有足够的容忍度。

**第四层：真人说话验证最终使用场景。** 五位真人（三男两女，不同口音）在不同位置说英语短句。中位定位误差 14 cm。另外测试了人的朝向影响：面对阵列（0°）时误差最小，超过 135° 后误差显著增大。还测试了距墙距离：离墙 > 60 cm 时定位正常，< 60 cm 开始恶化。

**最震撼的对比实验**：把 7 台机器人的 14 个麦克风挤在一个直径 10 cm 的圆环上（和散开的相同数量），precision 从 89% 以上降到 71%，recall 降到 54%。这个实验一刀切地证明了：系统的强大不是来自神经网络有多聪明，而是来自 aperture 有多大。分布式部署是不可替代的。

*所以这一节是想说：四层递进实验证明算法从仿真到真实的迁移损失可控，且"散开 = 大 aperture"是系统威力的根本来源。*

| Aperture（阵列孔径） | 麦克风之间最远距离 | 望远镜镜面直径——越大看越清 |

| Photointerruptor（光电对管） | 红外发射+接收器，靠反射探测 | 倒车雷达的红外版 |
| A\* 算法 | 经典最短路径搜索 | 手机导航推荐的最短路线 |
| Opus Codec | 低延迟开源音频压缩格式 | 微信语音消息的压缩技术 |
| BLE（蓝牙低功耗） | 蓝牙的省电子协议 | 手机蓝牙的"省电模式" |
| 匹配滤波 | 用已知模板在信号中找特定波形 | 在一锅杂音里找一段特定旋律 |

*所以这一节是想说：记住这 15 个词，后面任何声学 / 机器人论文你都能看懂大半。*

## 它有什么搞不定的

**1. 人背对阵列说话（头朝向 > 135°）**

实验数据显示：当说话人背对桌面上的机器人时，定位误差从 < 20 cm 飙升到 > 50 cm。原因是人后脑勺辐射的声波能量比正前方低 10+ dB，高频成分衰减更严重。而系统的定位精度依赖高频信号特征，吃不到就乱了。

**2. 人离墙太近（< 60 cm）**

墙壁反射产生强干扰，"幻影声源"聚类去重也压不住。定位误差显著上升。

**3. 桌上有大物体遮挡直达路径**

小物体（手机、笔）影响不大，但如果笔记本电脑横在两台机器人之间，1D 测距会出现长尾误差。2D 优化器能部分补救，但全面遮挡时会失效。

**4. 散开后桌面状态变化**

返航假设"来时的路上没有新放物体"——你散开后顺手放杯水，机器人原路返回时就会撞上去。截至论文发表（2023），没有动态路径重规划能力。

**5. 底座被人挪动**

整个坐标系是以底座为原点建立的。如果底座在任务中被人不小心挪了，所有 2D 坐标失效，分离输出变乱码。

**6. 只能在 2D 平面上工作**

机器人是轮式的，只能在硬质平面（桌面）上移动。沙发、地毯、不规则表面都不行。要推广到 3D 空间需要完全不同的硬件（比如无人机编队）。

**7. 实时性依赖主机 GPU**

所有神经网络计算在笔记本电脑上完成，机器人本地只做录音和压缩。如果主机 GPU 不够强，大模型无法实时。小模型实时了（1.82 秒处理 3 秒音频），但分离质量比大模型略差。

*所以这一节是想说：背对阵列、靠墙、桌面被改、底座被挪、不平表面都会让系统出问题——这些是后续改进的方向。*

## 它和别的几篇是什么关系

### 听觉三连的层级关系

本导读的 13 篇论文中，听觉方向有三篇组成"听觉三连"，它们是同一条技术栈的不同层：

| 层 | 论文 | 核心贡献 | 类比 |
|----|------|----------|------|
| 硬件/阵列层 | **Acoustic Swarms（本篇）** | 把麦克风从 1-2 个变成 14 个分布式 | 给你装上 14 只耳朵 |
| 神经处理层 | NeuralAids | 把降噪神经网络压缩到助听器芯片 | 给每只耳朵配一个小脑 |
| 决策/意图层 | Proactive Hearing | 自动判断"你在跟谁聊"，只放大同伴 | 大脑决定"听谁" |

三者的互补关系：Acoustic Swarms 提供了"大 aperture 才能分辨多人"的物理前提；NeuralAids 解决了"怎么在极低功耗下跑神经网络"的工程约束；Proactive Hearing 解决了"分离出来的多路声音该给用户听哪路"的决策问题。

如果未来要做一个真正的智能听觉系统，三层缺一不可。

### 同研究组的技术演进

Acoustic Swarms 出自华盛顿大学 Shyamnath Gollakota 组——这个组在听觉智能方向有连续多年的投入：

- **ClearBuds（MobiSys 2022）**：定义了"低带宽蓝牙音频流 + Opus 压缩 + 神经网络后处理"的工程范式。本篇直接沿用了这套音频传输方案。
- **Cone of Silence（NeurIPS 2020）**：提出"用神经网络做空间感知语音分离"的雏形，是本文分离网络的直接思想前身。
- **Proactive Hearing（UIST 2024）**：后续工作，聚焦用户意图驱动的声场过滤。

### 与机器人群文献的关系

- **Kilobot（Science 2014）**：千机器人自组装的开山之作，但用红外测距只能 10 cm 内。本篇用声波把工作距离推到 1+ 米。
- **Zooids（UIST 2016）**：桌面机器人 UI，但需要顶置投影仪——正是本篇要去掉的"外部基础设施"。

### 与视觉-语言-动作模型的关系

本篇提供的是"听觉感知层"的能力。在具身 AI 的全栈里，它可以为上层的 VLA agent 提供"听到客厅有人在说话 + 定位到具体位置"这类输入，补全视觉无法覆盖的 360° 感知死角。

*所以这一节是想说：本篇是听觉三连的"地基"，同时是 Gollakota 组多年听觉智能研究链条上的关键节点。*

## 思考题

**Q1：如果把 7 台机器人的 14 个麦克风全部固定在一个圆环上（不散开），系统性能会怎样？为什么？**

<details>
<summary>提示</summary>

论文做了这个实验：把 14 个麦克风挤在直径 10 cm 的圆环上，precision 从 89% 降到 71%，recall 从 89%+ 降到 54%。核心原因是 aperture 太小——麦克风之间的最大间距只有 10 cm，TDoA 值极小，不同方向的声源在 TDoA 空间里几乎重叠，网络分不开。这直接证明了"分布式部署"是系统威力的根本来源，不是网络架构。
</details>

**Q2：为什么定位阶段要在 3D 空间里搜索，而不只是 2D？**

<details>
<summary>提示</summary>

因为说话人的嘴巴高度（约 90–160 cm）远高于桌面上的麦克风（约 3 cm）。这个高度差会引入额外的传播时延——如果只在 2D 平面上搜索，会忽略这部分时延，导致 TDoA 对齐不准确，定位精度下降。在 3D 空间搜索后再投影到 2D 才能得到正确的平面坐标。
</details>

**Q3：SRP-PHAT 粗筛能把搜索空间缩小 200-446 倍，但为什么不直接只用 SRP-PHAT 做最终定位？**

<details>
<summary>提示</summary>

SRP-PHAT 是基于相位差的信号处理方法，分辨率受限于麦克风间距和信号带宽。它能给出"大概哪个方向有声源"的粗略估计，但无法精确到具体坐标，也无法区分高度差异。更重要的是，SRP-PHAT 在多人场景下容易产生"旁瓣"（假峰值），把回声误判为说话人。神经网络通过学习大量数据可以更好地区分真实说话人和反射伪影。两者配合是"效率 + 精度"的最佳组合。
</details>

**Q4：论文的分离网络用了"说话人间注意力"（inter-speaker attention）。如果去掉这个模块，只用"说话人内部注意力"，会怎样？**

<details>
<summary>提示</summary>

论文的消融实验（Fig. 6E）直接对比了有/无 inter-speaker attention 的性能差异。没有 inter-speaker attention 时，SI-SDRi 显著下降。原因是：如果每个说话人的分离器独立工作，它不知道"这段串进来的声音其实属于旁边那个人"，无法有针对性地抑制。inter-speaker attention 让网络在处理 A 的声音时同时"看到" B、C 的特征，从而识别并减弱来自 B、C 的串音成分。这是从"各自为战"到"协同作战"的关键一步。
</details>

**Q5：机器人散开时用"等分角度"策略。如果桌子是 L 形（不规则形状），这个策略还有效吗？**

<details>
<summary>提示</summary>

等分角度策略在不规则桌面上仍然可以工作，但效率会下降。例如 L 形桌子的凹角方向上，机器人很快就会碰到桌沿停下，导致那个方向的 aperture 很小。而在凸角方向上可能走很远。最终阵列形状会不对称，某些方向的空间分辨率会比其他方向差。论文用"桌面占用率"指标衡量效率，报告矩形桌子 > 75%。对于 L 形桌子，这个数字会更低。更智能的策略可能需要先探索桌面边界，但这会消耗更多时间和电量。
</details>

**Q6：论文假设"散开后桌面状态不变"。如果你是论文的后续研究者，你会怎么解决"有人在机器人散开后往桌上放了杯子"的问题？**

<details>
<summary>提示</summary>

几个可能的方向：（1）让机器人在返航时持续用声学测距检测前方是否有意外障碍物——如果测距突然变短（说明有东西挡在前面），则触发避障绕路。（2）机器人之间持续通信，如果某台机器人检测到路径被阻断，广播给其他机器人更新全局地图。（3）在底座灯塔持续监听所有机器人的 chirp，如果发现某台机器人的距离读数和预期不符，主动提醒重新规划路径。核心挑战是在厘米级机器人上实现实时避障——传感器和计算资源都极其有限。
</details>

**Q7：这个系统处理 3 秒音频，小模型用 1.82 秒。如果要做实时字幕（像 Zoom 那样边说边出字），这个延迟够用吗？**

<details>
<summary>提示</summary>

1.82 秒处理 3 秒音频意味着"刚好实时"——处理速度跟得上输入速度，但有 3 秒的初始延迟（因为要先积攒 3 秒的音频再处理）。对于会议记录或离线转写，这完全够用。但对于实时字幕（用户期望延迟 < 1 秒），3 秒的 buffer 加上网络处理时间意味着总延迟在 3-5 秒——体验会明显卡顿。要降低延迟，可以缩短处理片段长度（比如 1 秒），但分离性能可能下降（更少的上下文信息）。这是延迟和质量之间的典型 trade-off。
</details>

## 一些好奇心问答（FAQ）

**Q1：这个模型多大？我的电脑跑得动吗？**

论文没有公布确切的参数量。按 U-Net + Transformer 的典型配置估计在几十 M 到 100 M 参数级别（M = 百万）。一般家用 GPU（如 RTX 4070，12 GB 显存）推理肯定够。但真正的瓶颈不是 GPU，是那 7 台带 chirp 的机器人——没有硬件就只能用仿真数据跑算法部分。

**Q2：训练数据从哪来？**

训练全用合成数据：用电脑模拟虚拟房间，把公开语音数据集（LibriSpeech、VCTK）随机放在房间不同位置，模拟反射后叠加，得到 14 通道混合信号。真实测试数据没公开（涉及参与者隐私）。

**Q3：代码开源吗？**

论文发表在 2023 年 Nature Communications，作者是华盛顿大学 Shyamnath Gollakota 组。算法代码可能部分开源，但硬件 BOM/PCB 设计文件不一定全公开。这种软硬一体的工作复现门槛极高——你不仅要跑通代码，还要造出 7 台一模一样的机器人。

**Q4：为什么不用更简单的方法，比如让大家戴麦克风？**

戴麦克风改变了交互形式——这篇追求的是"用户什么都不戴，桌上摆个底座就能用"的无感体验。这是产品定位的根本差异。类比摄像头 vs 穿戴设备：安防摄像头不需要被监控的人配合戴东西。

**Q5：能用在沙发上吗？或者地面上？**

不行。机器人是轮式 2D 移动的，只能在硬质平面（桌面）上工作。沙发、地毯、不规则地面都跑不了。要推广到 3D 涉及完全不同的硬件（飞行群或腿式群）。不过桌面场景（会议、聚餐、办公）已经覆盖了大量实际需求。

**Q6：会不会有隐私问题？**

能听清每个人说什么的家用设备同时也是潜在窃听器。论文没有讨论硬件级隐私保护方案（比如本地处理、可关闭的物理开关、端到端加密）。这是后续产品化必须解决的问题。

**Q7：这个方向接下来可能怎么发展？**

短期方向包括：加入动态路径重规划、支持更多机器人（论文验证了 7 台，更多台需要解决蓝牙带宽瓶颈）、降低主机依赖（在机器人端做部分推理）。中长期方向是和视觉、语言模型融合——让家用机器人能"听到声音 → 知道是谁在说 → 理解说了什么 → 主动响应"，形成完整的具身听觉闭环。

*所以这一节是想说：常见疑问的核心在于——这是个软硬一体的系统，复现门槛高，但覆盖的桌面场景需求很大。*
